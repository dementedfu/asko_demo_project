# Другая пара

Демонстрационное приложение личной мастерской чистки обуви: от описания состояния до согласованной оценки, работы, оплаты и возврата. Мобильный клиент и кабинет мастера работают с одной локальной базой.

[Открыть демо](https://shoe-care-design-dementedfu.syrupyhoneysuckle4.chatgpt.site) · [Спецификация](specs/001-shoe-care-demo/spec.md) · [Проверки](docs/VALIDATION.md)

## Что можно проверить

- Заявка с 1–5 парами, разными материалами и пожеланиями; восстановление черновика.
- Интерактивная карта загрязнений и повреждений: сторона, зона, категория, вид и выраженность; доступный список зон.
- Настоящая загрузка JPEG/PNG/WebP, предпросмотр, замена и удаление; до 8 фото на пару отдельно в каждой стадии, до 5 МБ исходного файла. Большие изображения уменьшаются до 1600 px по длинной стороне.
- Отдельное предложение и решение по каждой паре: согласие, запрос изменений, отказ от оценки или исключение пары.
- Приёмка с состоянием и комплектностью; пересмотр цены с причиной и обязательным новым согласием.
- Работа, пауза, прогноз готовности, контроль качества с доработкой, результат и рекомендации.
- Демонстрационная оплата с отказом/успехом, возврат по парам и вычисляемый итог заказа.
- Переписка, прочтение, внутренние заметки мастера, очередь и поиск, услуги/прайс, показатели, отзыв и повторная заявка.
- Адаптивный интерфейс, локальный Golos Text, PWA и доступ к загруженному демо без сети.

## Маршрут демонстрации

1. В роли **Клиент** нажмите «Рассказать о своей паре». Добавьте две разные пары, отметки и фотографии; отправьте заявку.
2. Переключитесь на **Мастер**. В «Заказы» найдите новый номер, оцените каждую пару отдельно.
3. Вернитесь к клиенту: согласуйте первую пару, запросите изменения или отклоните оценку второй. Отказ от оценки не исключает пару автоматически.
4. Мастер принимает обувь. При необходимости пересматривает оценку с причиной — без нового согласия старт останется недоступным.
5. После согласия: «Начать работу» → «Передать на контроль» → «Завершить контроль» → «Пара готова». Можно проверить паузу и доработку.
6. Клиент выбирает «Демо-оплата». Сначала можно сымитировать отказ, затем успех. Мастер подтверждает фактический возврат пары.
7. Заказ завершится после выполнения всех обязательств. Если исключённая пара уже была принята, её тоже нужно вернуть.

Для быстрого знакомства подготовлены 9 заказов №024–032: новая заявка, разные решения двух пар, пересмотр после приёмки, пауза с просрочкой, контроль, ожидание оплаты, частичный возврат, завершённый заказ и черновик. Синтетического клиента можно выбрать в профиле. Сброс демо требует подтверждения.

## Запуск

Нужен Node.js 22.12+; проверено на Node 24.22.

```sh
npm ci
npm run dev
```

Production и проверки:

```sh
npm test
npm run build
npm run preview -- --port 4173
npm run test:e2e
```

Playwright использует `/usr/bin/chromium`. На другой машине укажите `CHROMIUM_PATH` — путь к установленному Chromium/Chrome. Тесты запускают preview самостоятельно, если он ещё не работает. Production-файлы находятся в `dist/` и размещаются на обычном HTTPS static hosting.

## Стек и структура

React, TypeScript, Vite, React Router, Tailwind CSS, Dexie/IndexedDB, Lucide, Golos Text, Vitest, Testing Library и Playwright.

- `src/domain` — чистые правила, версии предложений и переходы.
- `src/data` — транзакционное хранение, фотографии и синтетические сценарии.
- `src/features` — клиент, конструктор, общий заказ и мастерская.
- `src/ui` — общие элементы, сессия и загрузка фото.
- `e2e` — браузерные сценарии.
- `.specify` и `.agents/skills/speckit-*` — Spec Kit 1.3.3 с интеграцией Codex.
- `docs/superpowers` — согласованный дизайн и план; `AGENTS.md` — правила дальнейшей работы.

Superpowers используется как установленный плагин среды Codex. Он не встраивается в пользовательское приложение. Spec Kit задаёт спецификацию и задачи; его команды запускаются агентом по необходимости, это не фоновые процессы внутри продукта.

## Границы демо

Все исходные имена, телефоны, сообщения и заказы синтетические. Платежи, доставка и сообщения эмулируются: деньги не списываются, курьер не вызывается, SMS не отправляются. Публичный репозиторий не содержит пользовательских фото: загрузки остаются в вашем браузере.

IndexedDB сохраняет данные на одном origin в одном профиле браузера. Роли переключают представление общей локальной базы, это не серверная авторизация. Устройства и разные браузеры не синхронизируются. Очистка браузера удалит демо; резервного копирования пока нет. После первоначальной загрузки ресурсов доступен офлайн-режим. Установка PWA зависит от браузера; в iOS можно использовать «На экран Домой».

Визуальное направление A: тёплый молочный фон и оливковые акценты. Шрифт заменён на Golos Text и загружается из пакета локально. Название «Другая пара» временное.
